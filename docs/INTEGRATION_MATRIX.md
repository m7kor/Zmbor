# Community change integration matrix

Every upstream PR or issue considered for this fork is listed here with the evidence
behind the decision. "Integrated" means cherry-picked with the original author kept,
rebuilt, and covered by the test suite in this tree. Upstream base: `ran-j/PS2Recomp@eb8688b`.

| Ref | Area | Problem | Decision | Evidence / notes |
|---|---|---|---|---|
| PR #304 (fixes #370) | Recompiler, delay slots | `decodeFunction` stops at `end`; a branch in the last word gets a synthetic NOP delay slot, silently dropping the real instruction (FIFA Street 2 virtual call crash) | **Integrated** + extended | Architecturally the word at branch+4 always executes (except an untaken likely branch). PR only fixes `decodeFunction`; both reslicing sites in `ps2_recompiler.cpp` cut the same way, so this fork also keeps the trailing delay slot in slices and makes the emitter decode the real word from the ELF section (with a warning) instead of a silent NOP. |
| PR #268 (fixes #262) | Recompiler, VU0 | `vcallmsr` read `ctx->vi[27]` from `uint16_t vi[16]`: out-of-bounds UB; `ctc2 $vi27` writes `ctx->vu0_cmsar0` | **Integrated** | VCALLMSR always starts at CMSAR0 (PCSX2 `COP2.cpp`: `vu0ExecMicro(VU0.VI[REG_CMSAR0])`). Field-tested by a third party on CoD: WaW Final Fronts. Growing `vi[]` to 32 (the suggestion in the #262 follow-up) is the more complete long-term model but touches the runtime context layout; deferred. |
| PR #310 (fixes #309) | Recompiler, VU0 | SQI/SQD used the load field layout (fs/it swapped, OOB `vi[16..31]` write); LQI/LQD/SQI/SQD/ILWR/ISWR accessed RDRAM `0..0x3FF0` (EE kernel area) instead of VU0 data memory | **Integrated** + hardened | Encoding checked against the COP2 macro layout (SQI: `fs`=bits 15–11, `it`=20–16) and PCSX2 `VUops.cpp`. This fork adds the vi0/vf0 hardwiring PCSX2 applies (no step of vi0, no load into vf0, no ILWR into vi0). Known gap kept from the PR: VU0 addresses 0x4000+ (VU1 register mirror) wrap inside 4 KB. |
| Issue #260 | Recompiler, delay-slot resume | Claims resuming in the delay slot of `b` must continue at the target | **Rejected (as proposed)** | Delay-slot resume entries are only created by sequential arrivals (a branch/jump/entry *into* the delay slot address), where the branch at slot−4 is not executed and falling through is correct. Exceptions inside a delay slot already resume at the branch (`raiseCop0Exception` sets EPC = `branch_pc`, BD bit). The reporter notes the change had no effect on their port. |
| Issue #258, PR #298, PR #347 | Runtime, invocation stacks | Interrupt/callback stacks are carved from the top of RAM, aliasing the main thread stack | **Next milestone** | #298's top-of-RAM fallback reintroduces the aliasing (demonstrated in #347). Stacks are cached per (thread, depth) and never released. Needs a design that places them outside title memory and releases them with their thread. |
| PR #284, PR #372 | Runtime, DMAC | `D_ENABLEW` not mirrored to `D_ENABLER` (#257) | Pending review | Overlapping PRs; #372 also adds MFIFO. |
| CodeGenerator `m_sections` | Recompiler | Member was `const std::vector<Section>&`; tests construct `CodeGenerator({}, {})`, leaving a dangling reference read by control-flow analysis | **Fixed in this fork** | Now an owned copy (sections hold only metadata + a data pointer). |
