This is a source-based first pass. The independent device timing, threading, resource lifetime and profiling audits remain open. The [architecture baseline](ARCHITECTURE_BASELINE.md) records local execution evidence separately.

## Ownership boundaries to verify next

- **ELF data.** The analyzer stores section records that reference the parser's ELFIO-owned buffers. Keep those records inside the parser lifetime. The runtime separately validates program headers and maps bytes to guest RAM. Run a common malformed-segment corpus through the two paths to characterize disagreements.
- **Scheduler and graphics.** `Kernel/EeScheduler.cpp` tracks an executor thread, while `gs/gs_frontend.cpp` uses separate locks for presentation, backend lifetime and snapshots. Device-order changes need a replay fixture and a review of lock order and callback lifetimes.
- **Host state.** Audio operations in `ps2_audio.cpp` lock shared state. Studio protects UI state in `GUI.cpp`, and the runtime's game override registry has its own mutex. Startup, shutdown and error paths across these interfaces are candidates for concurrency tests.
